# Gradio 实时流程展示设计

## 目标

在文案生成和按要求改稿期间，持续向用户展示当前阶段、已完成阶段和整体进度，避免用户只能等待最终结果。

## 当前情况

`Agent.start()` 已按顺序记录主要处理阶段，并通过 `progress(str)` 发出阶段消息；`app.py` 把每条消息交给 `gr.Progress`，但进度始终是 0%，页面也不保留已完成步骤。`Agent.revise()` 目前没有阶段进度回调。项目本地 Gradio 为 5.50.0，部署配置标明 Gradio 6.2.0；本功能不新增依赖。

## 设计

生成与改稿均采用同一套阶段清单和状态展示：

1. 理解需求并检索资料（已知型号时并行预取）
2. 平台规则与卖点规划
3. 图文编排与选图
4. 撰写文案或按要求改写
5. 事实核验与合规检查
6. 加载配图并整理结果

页面在任务运行时显示阶段清单、当前阶段、已完成阶段数和进度条。阶段切换时刷新界面；正在等待模型或知识库响应时，将当前阶段标为运行中，不展示虚构的子阶段百分比。任务成功、缺少资料、资料冲突或异常时，保留流程状态并显示对应结束状态和现有说明。

## 实现边界

- 复用 `Agent.start()` 已有步骤信息，规范化其进度事件，使 UI 能稳定识别阶段。
- 为 `Agent.revise()` 增加与生成流程一致的阶段事件。
- 在 `app.py` 中通过 Gradio 生成器逐步推送状态面板和阶段进度，同时保留现有结果、图片和 Markdown 下载输出。
- 不改变检索、写作、核验的业务决策，不增加定时轮询或外部任务队列。
- 阶段顺序与流程终态集中维护，避免文案和代码中的阶段数量不一致。

## 错误与终态

- 成功：所有适用阶段标为完成，显示最终结果。
- 缺少资料或资料冲突：显示此前完成阶段，并将当前任务标为已停止，展示已有原因。
- 运行异常：显示最后一个活动阶段和错误信息，不将后续阶段标记为完成。
- 改稿换平台时仍复用既有资料与事实策略；阶段面板描述实际发生的重新选图、改写和复核。

## 验收标准

- 点击生成后，页面立即出现运行中的阶段和非零的阶段进度。
- 每次后台阶段回调后，阶段清单能更新，已完成阶段有明确状态。
- 模型调用等待期间，页面持续显示当前处理环节。
- 成功、缺少资料、冲突和异常均能结束进度状态并显示可读结果。
- 按要求改稿时也能看到阶段变化，换平台时状态与实际流程相符。
- 现有结果报告、配图和 Markdown 下载不受影响。
- 使用 Gradio 5.50.0 本地依赖验证界面回调，并确保实现不依赖 6.2.0 独有 API。

## 自检

- 目标、阶段、错误状态和验收条件一致；异常或早停不会显示后续步骤已完成。
- 没有新增无关业务功能或依赖。
- 进度以阶段推进为准；长耗时步骤只显示运行中，不推算阶段内部百分比。
